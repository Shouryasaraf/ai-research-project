# Trace-Driven Controller Decision Pilot (Exploratory)

This is an **offline diagnostic**, not a migration experiment. The [MAWI samplepoint-B 2000-12-28 capture](https://mawi.nezu.wide.ad.jp/mawi/samplepoint-B/2000/200012281400.html) supplies only one-second traffic rates. Node resources, carbon, risk, benefit terms, security invariants, target readiness and thresholds come from `configs/scenarios/synthetic_small.json` and remain **modeled/synthetic**. No packet is replayed through the vFW testbed. No target is actually warmed, synchronized, routed, or migrated by this evaluator.

`vfw_research.trace_decision_eval` reuses the chronological 60/20/20 split and source-pinned CSV checksum. Source capacity is an explicitly hypothetical stress-test threshold: the 90th percentile of *training* traffic, **14.50664 Mbps** in this capture. It is not the MAWI physical link capacity or measured vFW capacity. At each of 146 held-out one-second opportunities, the forecaster predicts and all nine policies decide using the same prior observation. Only then is the next actual traffic value revealed and used to update the forecaster. Every opportunity resets to the scenario's ready, synchronized target; actions do not cause state transitions between opportunities. There were 15 samples exceeding the assumed capacity.

The original fixed-radius models used the scenario's `max_commit_interval_width_fraction=0.2`. With a mean width of about 4.8–4.9 Mbps against 14.50664 Mbps assumed capacity, the full controller returned `WAIT` on all 146 opportunities for both models and made no `COMMIT`. Reactive control committed on 109 opportunities, while prediction-only committed on 121 (rolling mean) or 123 (EWMA). Those counts are **different decision propensities**, not better throughput, avoided overload, unnecessary migrations, or fair operational cost comparisons. `WAIT` reflects an already-warm target under a wide interval; a cold target would receive `PREWARM`. A same-step capacity-exceedance label is post-hoc and cannot measure whether a preemptive migration would help.

After inspecting this pilot, an adaptive EWMA residual-window forecaster was added as an **exploratory** variant. It updates its radius only after observing the true next sample. On this same capture it retained EWMA point MAE of about 1.149 Mbps, achieved coverage 0.890 against nominal 0.9, and had mean width 5.417 Mbps. The full controller still returned `WAIT` on all 146 opportunities. This is not a forecast or migration improvement. The adaptive interval has no formal finite-sample coverage guarantee under serial dependence or shift, and reuse of the examined trace precludes treating this variant as confirmatory evidence.

An initial pilot record labeled all wide-interval, already-warm cases `PREWARM`. That exposed a controller semantics bug: prewarming an already-warm target does no work. The controller was corrected to return `WAIT` in that case, while preserving `PREWARM` for cold targets. The final v4 local decision record and counts above reflect the corrected controller; older exploratory records remain untouched for auditability.

In a separate post-development synthetic exploratory batch (five families, seeds 0–9), the adaptive variant's held-out-shift coverage averaged 0.915 versus fixed EWMA's 0.835, but its mean interval width was 19.526 Mbps versus 8.721 Mbps. Point MAE was unchanged because the point model is the same. This is the expected coverage–width trade-off, not a free improvement or a publication-grade comparison. The other families and immutable seed records remain in the ignored local batch output.

The trace-driven output stores every decision, timestamp, prior traffic observation, forecast, observed next traffic, gate reason, policy, model, and scenario/trace digest. Raw/processed pilot files are ignored under `artifacts/raw/`. To reproduce after locally obtaining the permitted MAWI capture and converting it as documented in the README:

```powershell
$env:PYTHONPATH = "src"
python -m vfw_research.trace_decision_eval --trace-csv artifacts/raw/mawi-200012281400-1s.csv --provenance artifacts/raw/mawi-200012281400-1s.provenance.json --scenario configs/scenarios/synthetic_small.json --output artifacts/raw/mawi-decisions-new-run.json
```

The next validation gate is a separate, predeclared trace-derived traffic replay through the isolated firewall path, with measured migration timing, loss, continuity, safety and fallback. A modern, independent traffic trace is needed before generalizing the gate configuration or claiming performance.
